# ОК · Нативный клиент для iPhone

SwiftUI-клиент Одноклассников для iOS 17+. Версия 0.2 использует API для профиля, друзей и личных фотографий. На iOS 26 интерфейс использует **Liquid Glass**; на iOS 17–18 остаётся системное оформление соответствующей версии.

## Что работает

- Системный вход ОК через ASWebAuthenticationSession: проверка адреса возврата и state, хранение пары токенов в Keychain. Параметры приложения 512005294190 уже включены в сборку.
- Реальный профиль: имя, аватар, местоположение и статус из `users.getCurrentUser`.
- Друзья: `friends.get` + `users.getInfo`, загрузка по 50 человек, поиск среди уже загруженных друзей.
- Личные фотографии: `photos.getPhotos`, постраничная загрузка, полноэкранный просмотр, системное меню отправки ссылки.
- Избранное на этом iPhone, темы, тактильный отклик, обновление и очистка кеша.
- SwiftData хранит снимок данных и избранное отдельно для каждого аккаунта. Загруженные изображения кешируются на диске (до 150 МБ), чтобы их можно было повторно открыть без интернета.
- Токены хранятся в Keychain с `WhenUnlockedThisDeviceOnly`. Выход удаляет токены, локальные данные и кеш изображений.

Пока **не подключены** лента, сообщения, публикации, серверные «классы» и изменение профиля. На этих экранах нет вымышленных данных вместо API. Избранное не отправляется на сервер ОК. Загружается личный альбом; обзор остальных альбомов — следующий этап.

## Подключение аккаунта

Приложение ОК уже зарегистрировано: **512005294190**, публичный ключ **CPGJMFOGDIHBABABA**. В настройках ОК должны быть включены клиентская OAuth-авторизация, **VALUABLE_ACCESS** и **LONG_ACCESS_TOKEN**, а в разрешённые адреса возврата добавлен **ok512005294190://authorize**.

Установите IPA и нажмите **Войти через ОК**. Ввод пароля и согласие на доступ происходят в защищённом системном окне. Клиент принимает только ответ для зарегистрированного callback с совпадающим state и полной парой access_token/session_secret_key. Затем проверяет пользователя через API и сохраняет токены в Keychain. Секретный ключ приложения в бинарник не включён.

### Срок сессии и продление

При входе клиент запрашивает `VALUABLE_ACCESS;LONG_ACCESS_TOKEN`. По [документации ОК](https://apiok.ru/ext/oauth/permissions), длинный `access_token` действует 30 дней и автоматически продлевается при вызовах API (не чаще раза в день). Отдельный `refresh_token` в этом клиентском потоке не используется. При восстановлении сохранённого аккаунта клиент также вызывает `users.getCurrentUser` с полем `uid`, чтобы проверить сессию и запустить её автоматическое продление, даже если профиль загрузился из кеша. Метод `auth.touchSession` не используется: у него лимит 10 вызовов в месяц на пользователя.

Первоначальный `expires_in` сохраняется как справочная дата: сервер может продлить срок без изменения строки токена. Клиент больше не требует входа только из-за этой даты; повторное подключение появляется после ошибки авторизации от API. Отсутствие сети при проверке сессии не отключает аккаунт и не скрывает кеш. Повторный вход возможен после истечения срока без продления, отзыва доступа или смены пароля.

После обновления со сборки, запрашивавшей только `VALUABLE_ACCESS`, один раз подключите аккаунт заново, чтобы выдать длинный токен. Разрешение `LONG_ACCESS_TOKEN` должно быть выдано самому приложению ОК; добавление его в запрос клиента не заменяет настройку на стороне ОК.

### Запасной способ: личные токены разработчика

Если клиентская OAuth-авторизация недоступна для конфигурации приложения, в раскрывающемся разделе **Личные токены разработчика** поддерживается документированный ОК способ получения токенов владельцем приложения. Этот способ предназначен для личного клиента владельца.

1. Следуйте [официальной инструкции создания приложения ОК](https://apiok.ru/dev/app/create). Добавьте платформу **OAuth**.
2. Сохраните публичный ключ приложения — **Application public key**.
3. Проверьте, что приложению выдано **VALUABLE_ACCESS**: это разрешение требуется для друзей и фотографий. Если разрешения нет, порядок запроса описан в [документации разрешений](https://apiok.ru/en/ext/oauth/permissions). Письмо в поддержку отправляет владелец приложения.
4. Внизу настроек приложения найдите генерацию токенов для своего аккаунта и получите **access_token** и **session_secret_key**. После выдачи новых прав перегенерируйте пару: старый токен не получит их автоматически.
5. Установите IPA. В стартовом экране введите публичный ключ и эту пару токенов. Клиент сначала проверит её вызовом API и только затем сохранит в Keychain.

**Не вводите в клиент секретный ключ приложения (Application secret key). Не отправляйте пароли и токены в GitHub, issues, Actions или чат.** В CI не нужны секреты ОК. Для REST-подписи используется выданный `session_secret_key`, а не секрет приложения.

Клиентский поток response_type=token основан на [официальном iOS SDK ОК](https://github.com/odnoklassniki/ok-ios-sdk), реализован через AuthenticationServices без внедрения старого SDK. [Раздел OAuth ОК](https://apiok.ru/en/ext/oauth/) сейчас ссылается на VK ID: если сервер вернёт только authorization code вместо клиентской пары токенов, приложение не будет считать такой ответ успешным входом. Ручная пара владельца остаётся запасным вариантом.

## Установка с Windows

1. Откройте [GitHub Actions](https://github.com/Erapchu/ok_ios/actions/workflows/ios.yml), дождитесь успешной сборки **iOS · Test & IPA**.
2. Скачайте артефакт **OKNative-unsigned-ipa** и распакуйте ZIP. Внутри находится `OKNative-unsigned.ipa`.
3. Установите [Sideloadly](https://sideloadly.io/) и драйверы Apple по инструкции на его сайте. Подключите iPhone по USB и подтвердите доверие компьютеру.
4. Перетащите IPA в Sideloadly, выберите iPhone, укажите свой Apple ID и нажмите **Start**.
5. Если iOS попросит, подтвердите разработчика в **Настройки → Основные → VPN и управление устройством** и включите **Режим разработчика** в разделе **Конфиденциальность и безопасность**.
6. Откройте **ОК Нативный** с рабочего стола и подключите аккаунт.

При обновлении используйте прежние Apple ID и Bundle ID, чтобы сохранить данные. Бесплатная подпись обычно действует 7 дней; Sideloadly умеет обновлять её автоматически. Подробности — в [FAQ Sideloadly](https://sideloadly.io/faq.html).

## Liquid Glass и сборка

Проект собирается **Xcode 26.3** на `macos-15`. SDK выбран явно: стандартные TabView, NavigationStack, панели и листы получают системное оформление iOS 26. Кнопки используют `.glass` / `.glassProminent`, плавающие элементы управления — `glassEffect`. Эффекты доступны через `if #available(iOS 26.0, *)`; на более ранних системах используются стандартные кнопки и Material. Стеклянный слой применяется к управлению и навигации, содержимое остаётся читаемым.

Откройте `OKNative.xcodeproj` в Xcode 26+. Внешних Swift-пакетов не требуется. Bundle ID: `app.erapchu.oknative`. Для запуска на устройстве из Xcode выберите свою Team. GitHub Actions тестирует проект на iOS 26, архивирует arm64-приложение без подписи и упаковывает IPA; Sideloadly подписывает его отдельно.

```bash
python3 scripts/generate_project.py --check
python3 scripts/verify_project.py

# macOS, укажите установленный симулятор
xcodebuild test -project OKNative.xcodeproj -scheme OKNative \
  -destination 'platform=iOS Simulator,name=iPhone 17,OS=26.2' CODE_SIGN_IDENTITY=-

xcodebuild archive -project OKNative.xcodeproj -scheme OKNative \
  -configuration Release -destination 'generic/platform=iOS' \
  -archivePath build/OKNative.xcarchive CODE_SIGNING_ALLOWED=NO
bash scripts/package_ipa.sh
```

После добавления/удаления Swift-файлов выполните `python3 scripts/generate_project.py`. Симулятор использует локальную подпись и отдельные `Simulator.entitlements` для тестов настоящего Keychain. Для архива iPhone они не применяются.

## Проверки и снимки экрана

XCTest проверяет адрес и state OAuth, обработку отказа, сохранение непрозрачных токенов без повреждения URL-кодированием, подпись по фиксированному вектору, отсутствие токена в API URL, ошибки в HTTP 200, декодирование ID без потери точности, частичный отказ разрешений, загрузку снимка, кеш, изоляцию аккаунтов, выход и защиту от запоздалого ответа после выхода, HTTP и Keychain. Тестовые HTTP-ответы подставляются через URLProtocol; тесты не используют настоящий аккаунт ОК.

В `iOS-diagnostics` сохраняются результаты тестов, журналы и доступные скриншоты. На macOS runner приложение устанавливается в симулятор и снимается командой `xcrun simctl io <UDID> screenshot <path>`. Стартовый экран снимается в обычном режиме; заполненный профиль — с аргументом `--preview-demo` **только в Debug**. Release-сборка этот аргумент игнорирует и не предлагает демо-вход.

Ресурсы тестового предпросмотра описаны в [ASSET_CREDITS.md](ASSET_CREDITS.md). Успешная сборка и проверки на тестовых ответах не заменяют проверку настоящей пары токенов: живой доступ зависит от регистрации, разрешений и фактического ответа ОК.

## Архитектура

`OKAPIClient` подписывает параметры по [протоколу ОК](https://apiok.ru/en/dev/methods/), отправляет POST на `https://api.ok.ru/fb.do` через URLSession и Swift Concurrency. API-сессия ephemeral: без URL-кеша и cookies. Серверные тексты ошибок не показываются напрямую, чтобы не вывести токены из ответа. `OKSocialService` преобразует DTO API в модели экрана. `AppStore` управляет сессией, SwiftData, пагинацией и локальными реакциями на MainActor. `MediaCache` кеширует HTTPS-изображения отдельно и ограничивает размер диска.
